## Findings

1. **should-fix**, `games/cat-cafe/src/client/UI/Screens/HUD.luau:1028-1030`, `:2577-2585`, `:2850-2851` against `docs/design/cat-cafe/ui-contract.md:674` and `docs/design/cat-cafe/easy-start.md:50-62` (F87 small HUD). The Store tile is not in `PILL_KEYS` or `Components/HudUnlocks`, so a brand-new player on live now sees the gold, glowing, shining Store tile from tutorial step 0, next to the few pieces the small HUD allows (money, hint, My Cafe, Alley, Tutorial, Settings). The tile also makes the menu fold tab show at step 0 (`_menuFold.Visible = shown > 0 or store.Visible`), and that line's comment says the tab is hidden for an empty menu (F87). Before this change the tile never showed on live, so the conflict didn't come up. This is a design call for Derek, not a code bug. Option A: add a `store` HudUnlocks key (step 5 or Tier 2, say) and make `setStore` show the tile only when it has an `open` function and `_open("store")` is true. `_renderUnlocks` would have to re-apply the same rule, since `setStore` sets `Visible` directly today. Option B: keep it always shown and add the Store to the F87 lists in ui-contract.md (Small HUD) and easy-start.md 2f as an exception. Either way, the contract should say which.

2. **should-fix**, `HUD.luau:1031-1066` (glow plus endless shine sweep) with `.claude/skills/ui-review/SKILL.md` section 5 ("a permanent upsell button", "glow ... added to fill space"). The tile is now a permanent button whose glow and shine run forever, and it opens a shop where every card says "Soon" until launch. That's a lot of attention on something nobody can buy. No monetization-policy rule is broken (see "Policy" below), but it is on the anti-slop list. Suggest: run the shine (and maybe the glow) only while at least one pass is on sale, i.e. keep a `forSale` check for the decoration and not for whether the tile shows. Or record Derek's OK in the contract. Report only; not fixed here.

3. **should-fix**, `docs/playtests/test-plan.md:314`. The `StoreLogic.spec` row still ends with "the gold Store tile shows only while a pass is on sale." The `anyForSale` spec it describes was removed. Drop that clause.

4. **nit**, `games/cat-cafe/tools/cloudcheck/uigate-scenes.luau:1259-1265`. Both lookups use a recursive `FindFirstChild("Store", true)`. Today they hit the right instances: the HUD has exactly one descendant named `Store`, the tile (`Button.new{name = item.name}`, HUD.luau:982-983; under `Root` with a mouse, under `Menu` on touch). Under `CatCafeModals` the only `Store` is the Panel frame (`Screens/Store.luau:81`, Panel sets `Name = props.name`). `Modal.register` doesn't rename frames; it parents them to `Root.Container`. But any later descendant named `Store` (a Menu-list row, a shop card key, a tab) would be matched silently. Suggest looking the window up the way `press()` does (`CatCafeModals.Root.Container:FindFirstChild("Store")`, not recursive), and for the tile using `hud.Root:FindFirstChild("Store") or hud.Root.Menu:FindFirstChild("Store")`. The window assert is sound: `Scenes.close` runs 0.6 s on the virtual clock, so the previous scene's (StoreSoon) pop-out finishes and sets `Visible = false` first, and `Modal.register` starts frames hidden. So a press that opens nothing does fail. `tile.Visible` checks only the tile itself, not a folded menu or a disabled ScreenGui. That's fine for this scene.

5. **nit**, `games/cat-cafe/src/client/UI/init.luau:5222-5233` (`UI.store.reset`). Reset destroys the Store screen and sets `shop.open = false`, but leaves the HUD tile showing with a closure that toggles a window that no longer exists. Today this is harmless: `start()` is called only from `UI.init`, after `hud = HUD.new` (init.luau:681 before :1292), and `UI.destroy` destroys the HUD right after the reset (:1403-1406). A `if hud then hud:setStore(nil) end` in reset would keep the tile matched to `shop.open` if the block is ever restarted on its own.

6. **nit**, `games/cat-cafe/src/client/UI/Theme.luau:52`. The comment cites `#1016` (the PR). The contract (ui-contract.md:42) cites the issue `#961` for the same change. Use `#961` to match.

## Asked-about checks

- **(a) Lifecycle.** `refresh` computes `open = screen ~= nil` (init.luau:5162). `start()` calls `reset()` first, which disconnects `changed`, destroys the old screen, sets `shop.open = false` and calls `PassShop.stop()`. It then makes the screen, connects `PassShop.changed` and calls `refresh()`, which shows the tile. Hiding happens only through reset plus HUD destroy. Across `UI.destroy` and a re-init, the `initialized` guard and the order (destroy calls `store.reset` and then `hud:destroy`; init makes the HUD and modal before `store.start`) leave a fresh HUD whose tile starts hidden (HUD.luau:1029), and `shop.open` is false, so `refresh` shows it again. If `hud` were nil at start, `shop.open` would stay false and the next `UI.store.render()` from `UI.render` (init.luau:497) would show the tile once a HUD exists. In practice `hud` is never nil there. If `modal` is nil, `start` returns with no screen and the tile stays hidden, which is correct. No connection leaks: the `preview` field and its disconnect were removed together.
- **(b) Leftovers.** `rg "StoreOpen|anyForSale"` over the repo (excluding node_modules and .git) finds only the contract's own history sentence (ui-contract.md:840). Nothing in tools, tests, Demo or other scenes. `Scenes.close` no longer clears the attribute, and no scene sets it. The only stale prose is test-plan.md:314 (finding 3).
- **(c) Lookups.** Correct today, fragile later (finding 4).
- **(d) Policy.** Monetization-policy is clean. Nothing random, no timers, no pressure copy. Prices come from Roblox, and "Soon" shows while a pass is off sale. Off-sale buttons are made with `enabled = false` (Store.luau:229) and `Components/Button` drops `Activated` while disabled (Button.luau:508-512). `PromptGamePassPurchase` on an off-sale pass would be refused by Roblox anyway. The empty state ("Nothing in the Store yet") still covers no passes made. ui-review and F87 conflicts are in findings 1 and 2.
- **(e) Style.** Every changed Luau file keeps `--!strict` (uigate-scenes.luau is `--!nocheck`, as before). `Workspace` is still used across init.luau (GetServerTimeNow and others), and `StoreLogic` is still used in the block (`rows`, `passIds`, the `Price` type). `PassShop.prices()` is still used by `refresh` and `onOpen`. No `PassShop` or `StoreLogic` function was left without a caller. `git diff --check` is clean. StyLua and selene were not run (no toolchain here).
- API hygiene: no new Roblox APIs in the diff.
