# Review: design v0.3 (PR #27, docs only)

Reviewer: luau-reviewer thread, 2026-10-26 about 19:20 UTC. This is a security and data review of `data-model.md` v0.3, done before any code exists, so the engineer can build each feature with these points in. Section numbers below are data-model sections.

## Sign-offs asked for

| Item | Verdict |
|---|---|
| Net judged on the server (section 10) | **Signed off**, with S23 and S24 built in. |
| Carry bumps (section 10c) | **Not yet.** As written, the bumper can net the cat they just knocked loose, and a failed re-catch can lose the cat for good. S25 and S26 close both, and then it is signed off. |

### Net: closing circles

The design is sound. The server owns the schedule and stamps each press on arrival, and the client never sends a time, so a Perfect cannot be forged. The remaining risk is a script that watches the circles and presses on time. I accept it as Gavin's call: streaming the circles one at a time would not stop it, because the client has to know each circle's shrink time to draw it. Latency is corrected by half of `GetNetworkPing()`, capped at 0.15 s. An exploiter gains nothing from ping, because with the schedule in hand they can just send early.

**S23 (should-fix) The exploit check has to run on the server, and the spread condition would miss scripts.** Compute per-circle error from the server's own stamps, never from `TelemetryReport`, which the client can write anything into. Drop "error spread under 10 ms". Network jitter alone spreads a perfect script's arrivals by 10 ms or more on most connections, so that clause would hide exactly the players it is meant to find. Flag on Perfect rate above 95% over 50 or more circles, from the server's numbers. Honest players on Basic and Sturdy nets will not hold that rate through jitter.

**S24 (should-fix) A circle's deadline must end before the next circle starts.** A circle with no press closes at `target + good + CatchLatencyCapSeconds`. The next one starts at least `CircleGapMin` after the target. Today that is 0.18 + 0.15 = 0.33 s against a 0.35 s gap, a 20 ms margin, and section 10 suggests widening `good` first if the Basic Net feels mean. One step wider and a late press for circle i could land on circle i + 1. Add a Config spec: `CircleGapMin > max(good over net levels) + CatchLatencyCapSeconds`.

**N28 (nit, for QA)** The Basic Net's Perfect window is 45 ms each side. Phone ping often wanders by 30 to 50 ms, so honest mobile players will see Goods where they pressed on time. The feel test in section 10 should include a phone on mobile data, not just Wi-Fi.

### Carry bumps

The protections in 10c are good: grace, a safe zone at the door, two cooldowns, immunity after a re-catch, and the off switch. Two gaps turn a bump into a way to steal or destroy a cat.

**S25 (should-fix before sign-off) The bumper can net the cat they knocked loose.** "Anyone can net it, the old carrier included" covers the bumper too, and the only wait is DropProtectSeconds (2 s). A script fires `GrabBegin` the moment protection ends, then auto-presses the circles, and that is a steal: teleport next to a carrier, bump, grab. Fix: the bumper can never grab the stray they dropped (store `DroppedBy` on the server), and the old carrier gets the first claim for a short window (for example 8 s) before anyone else can grab it. Then "the bumper never receives the cat" is true.

**S26 (should-fix before sign-off) A dropped cat can flee for good.** Section 10 says that on a failed catch anything rarer than Common flees. So a griefer who knocks loose a kid's Legendary turns a re-catch into a coin flip on losing it. Fix: a stray with `Dropped` true never flees on a failed catch. It stays until someone catches it or the next night start.

**N29 (nit, for the build)** Reject a bump where target and bumper are the same player. Check `targetUserId` with `Guard.int` and `Players:GetPlayerByUserId`. Keep grace, immunity and cooldowns in server tables, and treat the character attributes as display only. The 6-stud range check uses character positions that the client owns, so it bounds honest play only. The cooldowns are what limit a teleporting exploiter; that is acceptable, just know it.

## Other v0.3 findings

**S27 (should-fix) Dealer stock can be rerolled by changing servers.** `nightIndex` counts nights since this server started, and every server has its own clock. On another server the seed differs, so the stock is new. `profile.dealer.night` also stops matching, so the bought marks reset. A player can hop until Star Treat shows up, and buy each slot again on every server. Fix: seed and mark purchases by a global window from `os.time()` (for example `floor(os.time() / DealerWindowSeconds)`), not by the server's night count. The cart can still appear only at night.

**S28 (should-fix) A rescue attempt has no time limit, and a retry race lets one player hold a trap.** With RescueLockSeconds removed, "the attempt holds the lock", but nothing ends an attempt if the player stops pressing. After a failed attempt, the same player and everyone else can try again at RetryAt (3 s), so a script that re-locks at that exact moment holds the trap forever. This is the v0.2 S20 pattern again. Fix: end an attempt at a deadline (the challenge length plus slack) and when the player leaves. Make the same player wait longer than others after a fail (for example 6 s against 3 s), or carry over the S20 tenure cap.

**S29 (should-fix) Rich tips need to be tied to their owner.** Plots are reused when a player leaves, and `RichTipAmount` sits on the plot. Release must clear both attributes and cancel the expiry credit, and the expiry credit must check it is still the same owner (UserId plus a serial), or the next player claims the last owner's tip. To pay exactly once, zero the amount before crediting, on both the claim path and the expiry path. Decide what happens when the owner leaves before expiry: credit it in the save-on-leave path, or drop it.

**S30 (should-fix) RenameCat input and filtering.** Count length with `utf8.len` after trimming, not `#`. Reject control characters and newlines. Reject `<` and `>` if any label that shows names has `RichText` on. Stored names are shown to other players for as long as the cat works. The safer pattern is to keep the raw name and filter it again for display when the cat is placed or the profile loads (working cats only, at most 10), because the filter changes over time. The refuse-on-error path in section 4 is right.

**S31 (should-fix) Migration safety.** Freeze the v2 `cafe_level` and `park_access` cost tables inside `ProfileSchema`, because the live Catalog will no longer have them. Also guard the other direction. `ProfileSchema.migrate` today rebuilds any saved data into the current version, so a v0.2 server that loads a v3 profile would drop `tier`, `bait`, `dealer` and cat names, and save that. Ship a guard with v3: if `raw.version > VERSION`, do not load and do not save, and ask the player to rejoin. When v3 is published, restart all servers.

**N30 (nit)** The rolled bait (`catId`, `variant`) should stay off ProfileSync until it is ready. Sending it early is harmless for security, since nothing can cancel it, but it spoils the reveal. Likewise, a stuck cat's shiny must not show through its model or prompt before the rescue succeeds.

**N31 (note, monetization)** Foods are bought with coins only, so they are not paid random items today. If a coin product for Robux is ever added, `BuyLure` and `BuyDealerFood` become paid random items. They then need the PolicyService gate, and the odds shown before purchase (already designed) under `monetization-policy`.

## Checked and fine

- Bait rolled at placement and saved in `profile.bait`, with no cancel remote and food used either way: leaving and rejoining cannot reroll it.
- `RankUp` is checked on the server against `collection`, coins and the rarity rule. Tier only rises. Area checks on `GrabBegin`, `RescueBegin` and `Bump` keep the client-side gates cosmetic.
- `CatchPress` and `RescuePress` carry no time and are limited to 10 per second. Only the first press per circle counts, in index order.
- Night income split at phase boundaries, and offline gain from the day rate: server-side math only.
- Announce uses `DisplayName`, which Roblox already filters.
