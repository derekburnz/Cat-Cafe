- 2026-10-25: Code is Rojo synced from `games/cat-cafe/src`; UI is built in Luau under `src/client/UI` rather than hand-built in Studio. Why: text files diff, review and merge; agents can edit them.
- 2026-10-25: Shared workspace while there is no GitHub repo is the project folder `cat-cafe/`. Derek creates the private repo and pastes the folder in (docs/setup-guide.md step 2).
- 2026-10-26: https://github.com/derekburnz/purr-pot is the source of truth. The lead thread pushed the project folder as the first three commits on main; from now on changes go through branches and pull requests, and CI runs the check gate on each one. Why: Derek approved the push; the desktop session that was going to do it did not complete.
- 2026-10-25: No stealing cats from other players and no trading for now. Derek decided in the design thread; can be revisited after the friends alpha. Why: stealing drives griefing complaints with a young audience and trading drives scams. If the alpha feels flat, the first option is an opt-in raid during the carry phase, never base stealing.
- 2026-10-25: Art style is Cozy Cream. Derek: cozy game vibes. Why: warm, low-contrast room where the cats are the color; the style guide already uses it.
- 2026-10-26: Third-party agent skills and a docs MCP server are part of the repo (`.claude/skills/THIRD_PARTY.md` lists each with upstream, commit and license; ranking and skipped tools in `docs/tooling/skills-and-tools-survey.md`). Derek asked for tools like blender-skills, then for every part of Roblox dev, and said go. Why: they fill the planned studio-mcp-playbook, give agents a way to verify APIs without Studio, check the Phase 0 setup in one command and gate assets before export, all free and MIT. Copies are cherry-picked, never edited in place, and updated by re-copying. Not adopted: Roblox/studio-rust-mcp-server (archived 2026-04), paid Studio AI agents (billed outside the Max plan), Script Sync instead of Rojo, CLIs that want a .ROBLOSECURITY cookie (Mantle, rbx-cli), Jest Lua (runs only inside Roblox; TestKit stays).
- 2026-10-26: `build_all.py` writes `assets/cat-cafe/exports/gates.md` (PASS/FAIL per asset: triangle budget, floor contact, applied transforms, one palette material, UVs on swatch centers, naming) and, with `--render`, a five-view inspection sheet per asset under `docs/concepts/cat-cafe/views/`. ## Proposed
- Data saving library: ProfileStore (vendored single file, battle tested session locking) vs own thin wrapper over DataStoreService with UpdateAsync. Lead recommends ProfileStore. Engineer to confirm.

### Proposed by the game-designer thread (2026-10-25, from gdd.md v0.1)
- 2026-10-25: Cats earn passively once placed on a spot; customers are cosmetic in the slice. Why: one legible formula (cats x cafe multiplier) is easy to tune and to show in the HUD. A customer demand model is a Phase 3 experiment.
- 2026-10-25: Catching areas are shared; each player owns one plot on an 8-player server. First to grab wins, with a 3 s server lock per stray. Why: the race for rares is the social hook without stealing.
- 2026-10-25: Catch success is decided on the server from rarity, gloves and lure; the client timing ring adds at most 15%. Why: ring timing cannot be verified server-side, so its value is capped to make cheating worthless.
- 2026-10-25: Lure food odds are shown as percentages before purchase from day one. Why: if coins are ever sold for Robux, food becomes a paid random item and must already comply.
- 2026-10-25: Slice roster is 12 cats: Common Tabby, Tuxedo, Ginger, Smoke, Snow; Rare Calico, Siamese, Tortie, Bengal; Epic Sphynx, Ragdoll; Legendary Void. Golden and Galaxy become rate variants of any cat after the slice, not cats of their own. Why: Void is the hero in the sketches; variants reuse every model.
- 2026-10-25: All 40 launch cats come from one blocky cat rig with pattern, color and accessory variants. Why: content cost is the main scope risk.
- 2026-10-25: Offline earnings at 25% of the logout rate for up to one hour. Why: rewards returning without making active play pointless.
- 2026-10-25: Income is accounted lazily (coins plus lastTick) instead of a per-second loop per player. Recommendation to the engineer, who may change it. Why: cheaper and simpler to reason about.
- 2026-10-25: The vertical slice uses the data-model.md economy (placed cats earn incomePerSecond by rarity on spots, bought cafe_level, lazy lastTick accounting). The engineer's earlier per-serve Economy.luau draft was replaced by shared/Types.luau and Config.luau that follow the doc. Why: one model for engineer, UI and QA; the per-serve payout can return later as a cosmetic cadence on top of the same rate.
- 2026-10-25: A lured stray never flees from the player who lured it, stays reserved to them until caught or despawn, and the food is refunded on despawn. Why: fair for the player who paid coins, and it is the delivery guarantee the paid random items rules need if coins are ever sold (growth thread's monetization.md section 7).
- 2026-10-25: If a coins product ever ships, the product is hidden from players whose policy restricts paid random items; BuyLure is never gated. Why: their coins are all earned, so luring stays open to them.
- 2026-10-25: Genre-standard features (night cycle, events, variants, set rewards, playtime and daily rewards, codes, Renovate, Nap Pod, Catnip, quests, Adoption Van, passes) are scheduled by phase in docs/design/cat-cafe/common-features.md; none enter the slice except fast travel at P2. Derek asked for them on 2026-10-25. Why: they are what players of Steal an Egg and Roll a Fisherman expect, but the loop has to be proven first.
- 2026-10-25: Designer accepts the growth thread's analytics-plan.md and monetization.md proposals (12-step funnel, three recurring funnels, 12 custom events through one Telemetry module; four passes at soft launch, 2x Tips deferred, no cash product). Why: they extend the GDD without changing it.
- 2026-10-25: Daily Treat is a seven-stamp card with no reset on a missed day, and Catnip states its numeric effect on the shop card before purchase. Growth thread's notes, accepted by the designer. Why: streak resets are a known parent complaint and conflict with the no-pressure rule; luck boosts must be disclosed before purchase.

### Proposed by the cat stats thread (2026-10-26, "Build cat stats and equip best")
- 2026-10-26: Each owned cat has `charm` (0 to 100, rolled once at catch, 0.8x to 1.2x rate), `level` (1 to 10, +5% rate per level, earned by time placed) and `xp`; `rating = rarity rate x charm x level x variant`. Charm 50 is exactly 1.0x, so the starter Tabby and every existing balance number are unchanged. Why: Derek asked for cat stat mechanics before Gavin's answers; this is the smallest model that makes two cats of the same id differ and rewards keeping a cat placed, and none of it depends on how alleys, income or rebirths end up working. Numbers in data-model.md section 4b.
- 2026-10-26: Equip best is an exact assignment (Hungarian algorithm over at most 7 spots), not greedy by rating. Why: a weaker cat that is the only one that loves a free spot beats greedy, and players notice a "best" button that is not best. The solver is pure and unit tested against brute force.
- 2026-10-26: Save data is version 2 (adds `level`, `xp`, `charm` per cat and `renovations`). Version 1 cats migrate to level 1, xp 0, charm 50 so nobody's income changes. Why: forward-only migration per section 14, no reset of the friends' saves.
- 2026-10-26: Income now multiplies by `prestigeMultiplier = 1 + 0.25 x renovations`, which is 1.0 for everyone until Renovate ships. Why: the rebirth seam exists in one place (Economy.incomePerSecond) so Gavin's rebirth answer plugs in without touching cats, spots or the UI. If income becomes customer driven instead, that same function is the one to replace.
- 2026-10-26: Charm is rolled on the server in `CafeService.addCaughtCat` unless the caller passes one. Recommendation to the engineer: roll it in `CatService` at spawn and set `Charm` and `Stars` attributes on the stray so the catch prompt shows stars before the grab (the UI already reads both). Why: seeing a five-star stray before grabbing it is the fun part.
- 2026-10-26: Cloud threads can run StyLua through its WebAssembly npm build (`@johnnymorganz/stylua`, same settings as `stylua.toml`), so formatting no longer waits for Derek's PC. Proposed for `tools/cloudcheck`: add a `format.mjs` next to `run-tests.mjs`. Why: the reviewer found 100-column lines in two new modules that the cloud could not check.

### Proposed by the ui-designer thread (2026-10-26)
- 2026-10-26: The UI reads ring timing only from `Shared.Config` (`GrabHoldSeconds`, `RingGoodWindow`, `RingPerfectWindow`) and draws the band at the end of the shrink. A hold that runs its full length fires no `grabEnded` (the UI shows "Missed" and waits for the server), and the client's ring result is a hint the server ignores. Why: the server scores timing from GrabBegin to GrabEnd (data-model section 10), so one set of numbers keeps the two sides from drifting, and a GrabEnd sent at 1.5 s would score as perfect.
- 2026-10-26: `src/client/UI/Types.luau` re-exports the shared catalog types (`CatDef`, `UpgradeDef`, `DecorDef`, `LureDef`, `SpotDef`, `Rarity`) instead of declaring look-alikes, so the client controller passes `Catalog.*` into `UI.init` with no cast. The UI's state types (`PlayerState`, `CatInstance`) stay its own, with optional cat-stats fields. Why: reviewer finding S9; duplicate shapes drift and hide type errors behind `any`.
- 2026-10-26: HUD and screen mockups live in `docs/concepts/cat-cafe/ui/index.html` (the "HUD mockups" row of the folder table), not `assets/cat-cafe/ui/`. Why: the page is a review document built from the asset thread's renders, not a Rojo-synced asset.

### Proposed by the asset-artist thread (2026-10-26)
- 2026-10-26: FBX exports use Roblox's documented Blender axes, Forward Z and Up Y, so a model facing -Y in Blender faces -Z (the LookVector) in Studio. Every position and angle in `exports/manifest.json` also has a `_roblox` twin, so code never converts axes by hand. `.claude/skills/asset-pipeline/SKILL.md` (lead-owned) still says "Forward -Z, Up Y" in its export step and should say "Forward Z, Up Y". Why: the engineer found that Forward -Z puts every front at +Z, so models would walk backwards under `CFrame.lookAt` and the carried pose would sit behind the player.

### Proposed by the sound-designer thread (2026-10-26)
- 2026-10-26: Audio uses classic `Sound` objects in four SoundGroups (Music, Ambience, Sfx, Ui) built in code by `src/client/Audio/` from one cue table (`Cues.luau`), not the newer Audio API. Every sound plays on the client; server scripts never play sounds. `settings.music` mutes Music, `settings.sfx` mutes the other three. Why: one object per sound and the most examples for a first Roblox game; client playback respects each player's toggles; the folder hides the engine, so a move to the Audio API later (acoustic simulation, voice effects) touches one place.
- 2026-10-26: The engineer adds `src/client/Moments.luau`, one signal per game moment (NetWindup, NetSwing, CatchSuccess, NightStart and the rest in `docs/audio/cat-cafe/sound-list.md` section 6), fired from the controllers; Audio and the vfx-animator's Effects only subscribe. Agreed with the animation and VFX thread. Why: a catch sounds and sparkles on the same frame, and neither cosmetic module wires remotes or reads state on its own.
- 2026-10-26: Audio asset ids live only in `src/client/Audio/Cues.luau`. Proposal to the ui-designer: `Theme.sounds` becomes an injected `playSound(cueId)` hook. Why: one place to swap a sound, and the UI never holds ids.
- 2026-10-26: Music follows the server clock: two day beds alternate, one night bed, a short stinger at each phase change. The slice uses Roblox Creator Store licensed music, which may only be used inside Roblox, so trailers and devlog clips need our own or separately licensed music. Why: free and already cleared for experiences; the Roblox-only limit is the one trap.
- 2026-10-26: Every audio file passes `.claude/skills/audio-pipeline/scripts/audio_gate.py` (Roblox upload limits, naming, mono for 3D, peak, loudness, leading silence, loop seams; report in `assets/cat-cafe/audio/gates.md`) and gets a sources log row before upload. Why: the agent cannot hear, so it measures; Derek or Gavin listens before a sound is final.
